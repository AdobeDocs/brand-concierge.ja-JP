# スキルと統合のフレームワーク {#skills-and-integrations}

統合（旧称ツール）とは、データソースまたはバックエンドへの接続のことです。 スキルは行動です。

1つの統合は、多くのスキルで使用できます。 1つのスキルで複数の統合を使用できます。 それらを個別に設定し、一緒にマッピングします。

## スキル

スキルはコンシェルジュの行動レイヤーです。 これは、コンシェルジュが行うことができる単一のジョブ（何を処理するか、いつステップインするか、どのように応答するか）を定義する、名前付きの再利用可能なユニットです。 スキルには独自のデータがありません。スキルに添付された統合機能から機能を借用します。

あらゆるスキルは、次の5つの部分で構成されています。

| パート | 概要 |
| --- | --- |
| 名前 | スキルのID |
| 説明 | そのスキルの目的はわかりやすいものです |
| 次の場合に使用 | トリガー条件です。 これは、このスキルを呼び出すタイミングをコンシェルジュに伝えるルーティング信号です |
| 統合 | このスキルが呼び出すことができる特定のツールを使用します。 スキルはここに添付されているものしか使用できません |
| 命令ファイル | スキルの動作とリクエストの解釈、レスポンスのフォーマット、ガードレールの適用方法を制御する詳細な手順 |

実行時のスキルの動作：ユーザーメッセージが届くと、プラットフォームは各アクティブなスキルの「使用時」トリガーと一致し、一致するスキルにメッセージをルーティングします。 その後、そのスキルは命令を実行し、その命令に添付された統合のみを呼び出します。 その指示は、ブランドプロファイルやその他のアクティブなスキルと並んで、コンシェルジュの全体的なランタイム動作に構成されます。

スキルは何をいつ実施するかを決めます。 それ自体はどのデータにも接続しません。それが統合の役割です。

## 統合

統合とは、コンシェルジュの機能レイヤーです。 実際にデータを取得したり、アクションを実行したりする外部システムやバックエンドシステム（ナレッジベース、コンテンツソース、ライブコマースカタログ）への接続です。 スキルが判断力であるところでは、統合は能力である。

あらゆる統合には、次のような特徴があります。

| 特性 | 意味 |
| --- | --- |
| 接続と資格情報 | 統合は、独自の設定（コマース環境IDやAPI キーなど）を使用してバックエンドに対して認証を行います。 この設定は、適切なデータソースをポイントするものです |
| 公開された機能 | 統合により、1つ以上の呼び出し可能な機能を利用できるようになります。これは、スキルが呼び出すことができる個々のアクションです。 たとえば、CommerceのMCPでは、商品検索、商品詳細、バリエーション、ファセット発見などを別々の機能として公開しています |
| 再利用可能 | 1つの統合は多くのスキルに添付でき、同じ統合は多くのコンシェルジュや顧客にサービスを提供します。 この再利用は、フレームワークの主要な効率性です |

実行時の統合の動作：スキルが起動し、データが必要であると判断すると、統合のツールの1つが呼び出されます。 統合は、ライブバックエンドに対して呼び出しを実行し、構造化データをスキルに返します。スキルは、その後、応答を形成するために使用します。

統合は機能を提供しますが、判断力を行使しません。 それはスキルによって呼び出されるのを待ち、特定の仕事がそれを求め、結果を返します。

### 機能と制限（セルフサービスの境界）

- **セルフサービス、エンジニアリングなし：**&#x200B;手順を編集し、「使用時」トリガーを編集し、既存の統合を添付または削除し、スキルを有効または無効にし、サポートされている統合（有効な資格情報を持つCommerce MCPなど）を接続します。

- **セルフサービスではない、必要なエンジニアリング：** カタログにまだ存在しない新しいツールまたはコネクタを作成するか、フレームワークでサポートされていない新しいガードレール カテゴリを追加するか、バックエンドで公開するデータを変更します。

- **2つのスキル間のトリガー重複は、設定のリスクとなります：** 2つのスキルが同じメッセージに対して実行される可能性がある場合、ルーティングに一貫性がない可能性があります。 ルータに依存して解決するのではなく、実際のあいまいさを避けるためにトリガーを書きます。

## すぐに利用できる統合機能

以下は、Composerの&#x200B;**統合を参照** パネルに表示される4つの統合です。

| 統合 | 機能 | メモ |
| --- | --- | --- |
| ナレッジベース検索 | Source：ブランドの製品情報、価格、機能、ドキュメントを、サイトクロールを通じて表示 | これはコンシェルジュの作成時に自動的に作成され、サイトクロールで入力されます |
| コンテンツAI 検索 | コンテンツ AIを利用して、ブランドのコンテンツを検索 | 別のコンテンツソース。通常、一度に必要なのは、ナレッジベース検索またはコンテンツAI 検索の1つのみです |
| エンティティリンク/製品カタログマッピング | ユーザーのメッセージ内の商品またはブランド言及を特定のカタログエンティティに解決します | 統合をサポートし、単独ではなく検索統合と並行して使用 |

## すぐに利用できるスキル

4つのスキルがカタログに含まれています。 それぞれに、推奨される統合が一覧表示されます。

| スキル | What it is for | 推奨される統合 |
| --- | --- | --- |
| サイトアドバイザリー | 一般的なブランド上の質問：ポリシー、FAQ、プログラム、ハウツー、サポート | ナレッジベース検索、コンテンツAI 検索、エンティティリンク |
| 製品アドバイザリー | 製品を見つけて調査する：名前ベースの製品カードと散文製品の質問 | ナレッジベース検索、エンティティリンク/カタログマッピング |
| Adobe Commerce Catalog Discovery | ライブカタログに対して、商品の詳細を検索、参照、フィルタリング、取得できます | CommerceのMCP ツール：Commerceの商品、商品の詳細、商品バリエーション、商品ファセット、検索可能な属性を検索します |
| Adobe Commerceと製品の比較 | Commerceのテーブル内の2つ以上の名前付き商品の並べて比較 | CommerceのMCP ツール：Commerce製品の検索、製品詳細 |

この2つのコマーススキルはカタログのみの機能で、ベースラインの一部ではないCommerce MCP統合に依存します。 非コマースコンシェルジュでは、代わりに自動作成されたナレッジベース検索に対して、サイトアドバイザリーと製品アドバイザリーが実行されます。

## コンシェルジュサービスの利用目的

ワンクリックでコンシェルジュを作成すると、ベースラインが組み立てられます。

| 作成時に接続 | 詳細 |
| --- | --- |
| ナレッジベース（データ） | アーリークロールでは、サイトマップで検索した上位10 ページから15 ページまで、ナレッジベースを作成します。 これはコンテンツストアであり、スキルや統合ではありません |
| ナレッジベース検索（統合） | 組み込みの統合機能。クロールされたナレッジベースに接続され、検索に使用されます。 このクロールは、クロールが作成した内容を示すものではありません |
| サイトアドバイザリー（スキル） | ベースラインでアクティブで、クロールされたナレッジベースを照会するナレッジベース検索を呼び出すためにワイヤー接続されています |

## よくある質問

**スキルと統合の違いは何ですか？**

インテグレーションとは、データソースやバックエンドへの接続のことです。ナレッジベースやライブコマースカタログなど、コンシェルジュが連絡できることです。 スキルは行動です。コンシェルジュが何を行うのか、いつ行うのか、どの統合を使用できるかを決定します。

**経験則：**&#x200B;統合は機能です。スキルとは、その機能をいつ、どのように使用するかに関する判断です。

**同じ統合を複数のスキルで使用できますか？**

これは意図的なものです。 Commerce MCPのツールは、カタログ発見と製品比較の両方で共有されています。 一度統合を構築し、多くのスキルと多くの顧客で再利用することは、2.0 フレームワークの中核となる効率性です。これは、顧客一人ひとりのカスタムビルドを取り除くものです。

**実務担当者は、エンジニアリングなしで完全に新しい機能を追加できますか？**

統合機能が既にカタログに存在する場合にのみ使用します。 実務担当者は、既存の統合を自由にマッピング、設定、指示することができます。つまり、セルフサービスです。 しかし、機能がまだ存在しないバックエンドまたはコネクタ（新しいAPIまたは新しいデータソースタイプ）が必要な場合は、まず統合を構築するエンジニアリング作業です。 カタログに存在すると、設定は再びセルフサービスになります。

**これはBC 1.0の単一のシステム プロンプトとどのように異なりますか？**

1.0では、動作は1つの大きなシステムプロンプト（マニフェスト）によって駆動され、安全に編集するのは困難で、一般的に変更するエンジニアリングが必要でした。 2.0では、マニフェストはまだ存在していますが、1つのブロックとして記述するのではなく、モジュール要素で構成されています。 そのため、実務担当者は行動を設定でき、単一のプロンプトに埋め込むのではなく、個々のガードレールと指示を読みやすく、監査しやすくすることができます。

**早期クロールは正確に何を作成しますか？**

このクロールでは、サイトマップで見つかった上位10～15 ページをもとに、ナレッジベース、つまりサイトのコンテンツを検索可能に保存する仕組みを構築します。 データレイヤーだけです。 クロールはスキルや統合を生み出すものではなく、後でアクションを起こすコンテンツを生成します。

**クロールでナレッジベースが作成された場合、ナレッジベース検索の統合は何ですか？**

ナレッジベース検索は組み込みの統合機能で、その仕事はそのナレッジベースを検索することです。 ナレッジベースはデータであり、ナレッジベース検索はそれをクエリする機能です。 それらは2つの別物です：一方はコンテンツであり、もう一方はコンテンツを読むツールです。 彼らを同じように扱うのはよくある間違いですが、彼らはそうではありません。

**コンシェルジュは、作成時、エンドツーエンドの一般的な質問にどのように回答しますか？**

3つのレイヤーが順番に機能し、スキル、統合、データモデルに正確にマッピングされます。

- 初期クロールでは、サイトのページ（データ）からナレッジベースが作成されます。
- 組み込みのナレッジベース検索統合では、そのナレッジベース（統合）を検索します。
- サイト アドバイザリースキルは、ナレッジベース検索（ビヘイビアー）を呼び出すために接続されています。
