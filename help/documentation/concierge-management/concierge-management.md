# コンシェルジュの管理

コンシェルジュは、ブランドのweb サイトから作成され、統合、スキル、指示、トーンおよびボイスの設定、ビジュアルスタイル、チャットコンポーネントを使用して調整できます。 コンシェルジュを訪問者に意図的にデプロイする前に、プレビューを使用して変更をテストします。

## 概要

| 項目 | 詳細 |
|---|---|
| プライマリユーザー | セルフサービス設定を使用するマーケター |
| 追加サポート | CommerceとB2Bを連携するには、コード、キー、IT部門、コマース部門、営業部門の設定が必要になる場合があります |
| 典型的な時間 | ベースラインコンシェルジュを作成するのに約5分。継続的な時間は、改良とテストに必要です |
| デプロイメント | 作成とは別：コンシェルジュを作成しても、web サイト訪問者には表示されません |

>[!NOTE]
>
>サンドボックスには、複数のコンシェルジュを配置できます。 各コンシェルジュには独自の設定があり、コンシェルジュはコンシェルジュリストから削除できます。

## コンシェルジュの作成

単一のweb サイト URLからコンシェルジュを作成することは、初めてのユーザーに推奨される出発点です。 システムは、手動で設定しなくても作業ベースラインを作成します。

1. ブランドのweb サイト URLを入力し、**作成**&#x200B;を選択します。

1. 生成されたブランド表現を確認します。 このシステムは、web サイトのトーンを分析し、フォーマル、暖かみ、遊び心、エネルギーなどの属性を提案します。 必要に応じて値を調整し、**続行**&#x200B;を選択します。

1. 生成されたブランドプロファイルを確認します。 プロファイルには、ブランド目標、製品やサービス、ターゲットオーディエンス、ブランド価値、主要な差別化要因、一般的なユースケースなどが含まれます。 必要に応じてプロファイルを編集し、**続行**&#x200B;を選択します。

1. 生成された開始手順、ガードレール、提案を確認します。 例えば、ガードレールから法的トピック、コンプライアンスのトピック、競合他社とのディスカッションなどを除外したり、フォローアップとして迅速なアイデアを提案したりすることができます。 必要に応じてコンテンツを編集し、**保存**&#x200B;を選択します。

1. システムがベースライン設定を適用するのを待ちます。 また、web サイトから生成された色やフォントを使用して、デフォルトのビジュアルスタイルを作成し、web サイトコンテンツに関連する一般的な質疑応答スキルなど、ベースラインスキルや統合を活用できます。

1. プレビューでコンシェルジュをテストします。 デスクトップビューとモバイルビューを使用できます。 **新規**&#x200B;を選択して、テスト会話を再開します。

>[!IMPORTANT]
>
>コンシェルジュを作成しても、訪問者には表示されません。 導入は、慎重な検討にもとづく個別のステップです。 設定は、デプロイメントの前にいつでも変更できます。

## 自動的に設定される内容を理解する

コンシェルジュを作成すると、次の項目が自動的に設定されます。

| 項目 | 設定 |
|---|---|
| ナレッジベースのコンテンツ | 自動的に始まる背景クロールを通じて、サイトのトップページから構築される |
| ナレッジベース検索の統合 | クロールされたコンテンツを自動的にポイントします |
| サイトのアドバイザリースキル | デフォルトで有効になっているので、一般的な質問にすぐに回答できます |

## スキルと統合について

コンシェルジュサービスの構築と設定に使用されるインターフェイスであるComposerでは、次のふたつの関連する概念を使用しています。

- **統合：** web サイトのコンテンツやライブ製品カタログなどのデータソースへの接続。 統合は情報を取得しますが、それ自体で意思決定はしません。
- **スキル：** コンシェルジュが何を行い、いつ行い、どの統合を使用できるかを決定する動作。

1つの統合で複数のスキルを使用し、1つのスキルで複数の統合を使用できます。 たとえば、単一の製品カタログ接続で、スキルごとに再構築することなく、複数の製品関連のユースケースをサポートすることができます。

## 統合の設定

**統合を参照**&#x200B;を選択して、使用可能な統合カタログを表示します。

| 統合 | 目的 | メモ |
|---|---|---|
| ナレッジベース検索 | Web サイトのコンテンツを検索 | コンシェルジュの作成時に自動的に設定 |
| コンテンツAI 検索 | AEM Sites コンテンツを検索 | AEM Sites as a Cloud Serviceのお客様向け |
| 製品カタログ | アップロードした製品リストの製品カードまたはリンクを表示します | 小規模な非コマースカタログ向け |
| COMMERCE MCP | Adobe Commerceのライブカタログに接続して、商品検索、商品詳細、比較を行えます | デフォルトでは有効になっていません。コマースまたはIT チームのコードまたはキーが必要です |
| ミーティング予約 | 訪問者が営業担当者との面談を予約できるようにし | B2B機能 |
| ライブチャット | 訪問者と営業担当者の連携 | B2B機能 |

### 統合を有効にして設定する

1. 統合タイルを開き、**編集**&#x200B;を選択します。

1. **ナレッジベース検索**&#x200B;で、検索するナレッジソースを選択します。 接続の名前を変更できます（例：`Website content`）。

1. **Commerce MCP**&#x200B;に対して、Adobe CommerceまたはIT チームから提供された次の値を入力して接続します。
   - 環境ID
   - web サイトコード
   - ストアコード
   - ストアビューコード
   - API キー

1. 「**保存**」を選択します。 統合は接続済みとして表示され、プレビュー、編集、または削除できます。

異なるナレッジソースをポイントするインスタンスなど、同じ統合の複数のインスタンスを追加できます。 特定の統合インスタンスを使用するようにスキルを設定できます。

### 確認が必要な統合情報

以下の詳細は情報源の資料では確認されておらず、製品ドキュメントとして公開する前に確認する必要があります。

- `experienceplatform.adobe.com`へのログイン用の完全な実稼動URL。
- コンシェルジュが統合インスタンスの数に制限があるかどうか。
- カスタムまたは独自の統合のためのロードマップとプロセス。これは計画通りに言及されましたが、詳細は示されていません。

## スキルの設定

訪問者がコンシェルジュに求められるサービスは、スキルによって決まります。 利用可能なスキルカタログを表示するには、**スキルを参照**&#x200B;を選択します。

| スキル | 目的 | 必要な統合または設定 |
|---|---|---|
| サイトアドバイザリー | FAQ、ポリシー、価格設定、ハウツーガイダンス、サポートトピックなど、企業に関する一般的な質問への回答 | Web サイトコンテンツ。デフォルトで有効 |
| Adobe Commerce Catalog Discovery | ライブカタログから製品に関する詳細を検索、参照、フィルター、取得します | Commerce MCPとの統合 |
| Adobe Commerceと製品の比較 | 製品名を並べて比較します | Commerce MCPとの統合 |
| 営業担当者との面談を予約 | ミーティングの予約を提案および促進 | ミーティング予約の統合 |
| 営業部門とのライブチャット | ライブチャットの引き継ぎを提案および促進 | ライブチャット統合 |

### スキルを有効にして設定する

1. スキルタイルを開き、**変更**&#x200B;を選択します。

1. スキルの名前、説明、意図を設定します。 インテントは、`pricing`や`compare products`など、スキルをトリガーにするフレーズやトピックです。 複数のインテントを追加できます。

1. スキルに統合が必要な場合は、必要な統合を添付します。 たとえば、コマーススキルにはCommerce MCPが必要です。 または、**推奨される**&#x200B;を使用を選択して、Composerで適切な統合が自動的に選択されるようにします。

1. 必要に応じて、スキルの開始手順を確認し、編集します。

1. **保存**&#x200B;を選択し、ライブプレビューで変更をテストします。

>[!TIP]
>
>2つのスキルが同じ質問に対応できれば、ルーティングに一貫性がなくなります。 スキルトリガーは、重複するインテントを使用するのではなく、明確かつ具体的に定義します。

### 確認が必要なカスタムスキル情報

このソース資料は、完全にカスタム化されたスキルを作成するための計画的な機能について言及していますが、ロードマップやプロセスは提供されていません。 この機能をサポート対象として文書化する前に、可用性とオーサリングの手順を確認してください。

## コンシェルジュサービスの利用方法

コンシェルジュの「指示」フィールドを使用して、ブランドガイドラインに沿った回答を提供します。 手順は次のように定義できます。

- 商標の使用
- 応答構造
- 回避すべきトピック

テキストフィールドに直接指示を入力します。 説明を保存すると、コンシェルジュは自動的にその動作を更新します。 ライブプレビューですぐに結果をテストします。

同じ領域には、次の編集可能コンテンツも含まれます。

- **ガードレール：** コンシェルジュが避けるべき行動またはトピック。
- **提案：**&#x200B;応答の後に表示できるフォローアップ プロンプトのアイデア。

## トーンとボイスの設定

トーンとボイスの設定では、応答の長さとトーン属性を次のように制御します。

- フォーマルまたはカジュアル
- 暖かいまたは中立
- 遊び心がある、または真面目な

選択内容は自動的に保存されます。 変更を加えた後、ライブプレビューで結果をテストします。

## ビジュアルスタイルの設定

ビジュアルスタイルの設定は、次のようなコンシェルジュの外観を制御します。

- カラー
- フォント
- ウェルカムメッセージテキスト
- 法的免責事項のテキスト
- カードカラー

ユーザーインターフェイスで設定を編集し、ライブプレビューを使用して変更を確認します。 変更を永続的にするには、**保存**&#x200B;を選択します。

>[!NOTE]
>
>ソース資料には、完全にカスタマイズされたルックアンドフィールは、別のデプロイメントスクリプトを介して、ユーザーインターフェイスで使用できるオプションを超えて可能である可能性があると記載されています。 デプロイメントスクリプトの手順は含まれていません。確認したら、別途文書化する必要があります。

## チャットコンポーネントの設定

チャットコンポーネントは、訪問者がチャットウィンドウに表示する個々の要素を制御します。 ユーザーインターフェイスでコンポーネントを選択して、サイドパネルで設定を開きます。

| コンポーネント | 制御するもの |
|---|---|
| チャットバブル | 訪問者メッセージとコンシェルジュメッセージの表示 |
| プロンプトまたはプロンプトピルを開始 | 特にモバイルで表示される件名で、開封時に提案される質問 |
| フォローアップの提案 | 回答の後に次の質問を提案 |
| 入力バー | 訪問者が質問を入力するために使用するメッセージボックス |
| 引用 | ソース参照が応答に表示されるかどうか、およびどのように表示されるかを示します |
| フィードバック | 各回答の後に表示される「サムズアップ」または「サムズダウン」の評価コントロール |
| 商品カード | 色やボタンなど、商品カードのレイアウトとスタイル |

## B2B機能の設定

ミーティング予約とライブチャットにより、訪問者は営業担当者とのミーティングを予約したり、営業担当者とのライブチャットを開始したりできます。 これらの機能は、Sales Qualifierと呼ばれるコンパニオン製品で実現されます。

### 役割と責務

- **マーケター：** Brand Conciergeのスキルと統合機能を設定します。
- **営業担当者：**&#x200B;独自のカレンダーを接続し、可用性を設定します。

### ミーティング予約またはライブチャットの設定

1. **統合を参照**&#x200B;で、**ミーティング予約**&#x200B;または&#x200B;**ライブチャット**&#x200B;を開きます。 デフォルトでは、組織内の全員が潜在的なチームメンバーとして利用可能です。この段階でチームメンバーを追加するために別の手順は必要ありません。

1. 各営業担当者に`experienceplatform.adobe.com`にサインインしてもらい、**Sales Qualifier**&#x200B;を開き、**プロファイル設定**&#x200B;に移動します。

1. 各担当者に、Outlookなどのカレンダーを接続してもらいます。 Microsoft Teamsは、オプションで含めることができます。 担当者は、ミーティングの招待状の件名とメールテキストを設定することもできます。

1. 可用性の設定。 可用性はデフォルトでカレンダーから取得され、次の方法でさらに制限できます。
   - 会議の長さ
   - ミーティング間のバッファー時間
   - 最低限必要な通知
   - 特定の使用可能な時間ウィンドウ

1. 同様のプロセスを使用して、ライブチャットの可用性を個別に設定します。

1. Brand Conciergeで、**管理対象メンバー**&#x200B;を開き、担当者が使用可能な状態で表示されていることを確認します。

1. **ミーティング予約**&#x200B;または&#x200B;**ライブチャット**&#x200B;の統合を有効にします。

1. **スキルを参照**&#x200B;に移動し、**セールスとのミーティング**&#x200B;または&#x200B;**セールスとのライブチャット**&#x200B;を選択します。 トリガーを設定し、対応するインテグレーションを添付して、スキルを保存します。

1. 「**シミュレート**」を選択して、エンドツーエンドのエクスペリエンスをテストします。 サンプル質問を入力し、適切なスキルとエンゲージメントフローにルーティングされていることを確認します。

### デプロイメント後の動作

機能が有効な場合：

- ライブチャットの受信トレイは、リアルタイムで代表者に表示されます。
- 予約されたミーティングは、ミーティングビューに表示されます。
- ミーティングのパフォーマンスレポートは分析画面で確認できます。
- ミーティングとチャットのエンゲージメントは、既存のアクティビティデータと共にアクティビティとしてMarketoに送信されます。

### 確認が必要なB2B情報

ソース資料では、次の項目が未解決と識別されています。

- ライブチャットには独自の分析ダッシュボードがありません。これは、ドキュメントのギャップではなく、進行中の製品のギャップと呼ばれています。
- Sales Qualifierの正確な`experienceplatform.adobe.com` ログインパス。
- ミーティング予約とライブチャットに個別のライセンスや使用権限が必要かどうか。

## プレビューリンクを共有

共有可能なプレビューリンクにより、関係者は、Composerにアクセスすることなく、コンシェルジュをライブ web サイトにデプロイすることなく、コンシェルジュを確認して操作できます。

1. コンシェルジュプレビュー画面から、共有可能なプレビューリンクを生成します。

1. レビュー担当者とリンクを共有します。

1. レビュー担当者は、Composerにログインしなくても、リンクを通じてコンシェルジュとやり取りできます。

### 確認が必要なプレビューリンク情報

この手順を完全な製品ワークフローとして公開する前に、次の詳細を確認してください。

- ユーザーインターフェイスでの共有アクションの正確な場所とラベル。
- プレビューリンクの有効期限が切れるか、取り消し可能か。
- プレビューリンクの使用状況をライブ分析とは別に追跡するかどうか。

## デプロイメント前のテスト

重要な設定変更のたびに、プレビューまたはシミュレーションのエクスペリエンスを使用します。 少なくとも、次の点を確認します。

- コンシェルジュサービスは、意図したweb サイトコンテンツからの一般的な質問に答えます。
- 各スキルは、意図したトリガーにのみ反応します。
- 必要な統合は接続され、正しいデータソースを指します。
- 製品検索と比較では、意図したCommerce MCPまたは製品カタログインスタンスを使用します。
- ミーティング予約とライブチャットは、目的の担当者にルーティングされます。
- トーン、音声、指示、ガードレール、提案により、期待される応答が生成されます。
- ビジュアルスタイルとチャットコンポーネントは、デスクトップとモバイルのビューで正しく表示されます。
- 関係者は、共有可能なプレビューリンクが使用されている場合は、そのリンクを介してエクスペリエンスを確認できます。
